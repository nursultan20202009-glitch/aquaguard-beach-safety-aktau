# AquaGuard Aktau — MVP для диспетчера спасателей

YOLOv8n обнаруживает **пловца в воде** на тестовом видео сверху. Простой трекер связывает рамки между кадрами. Если человек находится в красном секторе A 0,6 секунды, сервер создаёт событие «Человек в опасной зоне — проверьте», сохраняет кадр и запись в SQLite. Панель обновляется без перезагрузки. Спасатель принимает событие, видит точку на карте, добавляет заметку и закрывает случай. Есть печатная карточка инцидента.

**Модель не определяет утопление или снос течением.** Видео Ahmet Kurt / Pexels снято **не в Актау и не на Каспии**. Координаты (43.6260, 51.1735) — заранее заданная **тестовая точка сектора A** у Актау, а не вычисленная позиция пловца или GPS дрона.

## Запуск

Нужны Python 3.11+ и интернет при первой установке зависимостей. На Windows запустите `START-AQUAGUARD.cmd` либо в PowerShell:

```powershell
.\start.ps1
```

Скрипт установит зависимости в `.runtime` и поднимет локальный сервер. Альтернатива:

```powershell
python -m pip install -r requirements.txt
python server.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). `PORT` меняет порт. Данные сохраняются в `data/alerts.sqlite3`, кадры — в `data/evidence/`. Путь можно изменить через `DATA_DIR`.

## Показ за минуту

1. Откройте **Видеонаблюдение**. По умолчанию запускается водный ролик с реальным обнаружением пловца: рамка сначала зелёная, затем в секторе A красная. Если ролик закончился, нажмите **Повторить**. Кнопка **Обзор воды** показывает широкий ракурс, где пловцы слишком малы для надёжной детекции.
2. На вкладке **Тревоги** появится автоматическое событие с сохранённым кадром.
3. Нажмите **Принять тревогу**. Откроется **Карта и журнал** с тестовой точкой A и координатами. Это не точная позиция пловца.
4. Сохраните заметку, откройте **Печатный отчёт**, затем **Закрыть событие**. Статусы и время действий остаются в SQLite после обновления страницы.

## Состав

- `server.py` — HTTP API, обработка видео, YOLOv8n через ONNX Runtime, трекер ближайшей точки, проверка зоны и SQLite.
- `public/` — русский адаптивный интерфейс, опрос API каждые 1,5 секунды, карта Leaflet/OpenStreetMap и отчёт.
- `config.json` — координаты тестовой точки, красная зона на видео, время пребывания и защита от повторов.
- `assets/yolov8n.onnx` — готовая модель; `assets/swimmer-water.mp4` — проверяемый сценарий; `assets/beach-aerial.mp4` — обзор.
- `data/` создаётся сервером и не отправляется в Git.

API: `GET /api/state`, `GET /api/events/{id}`, `GET /api/frame.jpg`, `GET /api/snapshots/{id}.jpg`, `PATCH /api/events/{id}`, `POST /api/demo/restart`, `POST /api/demo/source`.

Другой файл, RTSP/HTTP-поток или камера подключаются через `VIDEO_SOURCE` (для камеры — `0`). `SOURCE_LABEL` задаёт подпись источника. Для иной точки задайте `ZONE_LAT` и `ZONE_LON`, а границы на видео измените в `config.json`. Подключение источника само по себе **не создаёт координаты человека**.

## Ограничения и публикация

Трекер ближайшей точки рассчитан на короткое демо и может менять ID при перекрытии людей. Карта загружает тайлы OpenStreetMap из интернета. GitHub хранит исходный код, но не запускает Python/SQLite сервис. Для публичного MVP нужен хост с Python 3.11+, постоянным диском под `DATA_DIR`, HTTPS и авторизацией перед панелью. Запустите один процесс с `HOST=0.0.0.0` и назначенным `PORT`, затем проверьте публичный URL, тревогу и сохранение статуса после перезапуска. Для эксплуатации нужны местное видео, калибровка зоны и геопривязки, оценка ошибок и испытания со спасателями.
